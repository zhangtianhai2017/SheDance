## 1. 核心哲学（灵魂 · 不可动摇）

### 1.1 一句话定义

> **SheDance 仿真的是"一个模仿能力强的人"。**
> 输出不是对输入动作的复制,而是**这具身体(有它自己的强处与短处)对意图的再创作**。

我们不追求"让仿真人精确还原捕捉到的动作";我们让**我们造的这个人,用他自己的身体,尽最大努力去模仿那段动作**。出来的是**这个仿真人**跳的舞。

### 1.2 输入是神圣的——不要动它(连消抖都不做)

- **输入 = 要模仿的"意图"**,不可修改。
- **唯一的变换发生在身体**(肌肉最大力 F_max + 肌肉动力学)。
- 任何"改输入"的做法(如消抖)都会**污染输入/输出的边界**,让"是谁的问题"分不清。所以**连消抖都不做**——让身体的物理极限去"消化"不可能。
- 进去的是意图,出来的是这具身体的演绎。边界清清楚楚。

### 1.3 肌肉能力(F_max)= 物理性过滤器 + 角色个性（一举多得）

物理事实:动捕抖动是高频位置噪声 → 二阶导(加速度)爆炸 → 需要的力爆炸。真人肌肉**根本产不出**那种力。于是用肌肉能力当上限,天然得到:

- **去噪(物理性)**:不可能的抖动需要超人力 → 肌肉产不出 → 被自然削平。不是通用低通滤波,是"这具身体能做到什么"。
- **角色个性 = "舞者内生模型"**:
  - F_max ×2~3 → 超常/刚猛的舞者;
  - F_max ×0.6~0.8 → 柔弱女子,自然跳得"软"、够不到极限动作;
  - 同一段意图,**不同身体跳出不同质感**。F_max(可分肌群)就是角色旋钮。
- **自洽**:不是 ad-hoc 参数,是物理。

> 注意:F_max 只在肌肉**饱和**(需求超过能力)时才"咬"。需求在能力内时,身体能精确跟随。所以角色差异在高难/高速动作处最明显。

### 1.4 任意输入 → 模仿（这扇门逻辑上已打开）

- 输入**不限于动捕、不限于标准舞蹈**:可以是大猩猩、提线木偶、甚至某台机器的动作。
- 系统只是"用自己的身体尽力模仿那些动作"。
- **通用形态:跟踪空间特征(手/脚/关键点轨迹、身体形状),而非逐关节角**——因为非人骨架无法逐关节对齐。当前人类舞蹈捕捉骨架相同,可先用关节角跟踪;但通用方向是关键点跟踪。
- 由此打开:**输入任意动作 → 生成模仿动作/舞蹈**。现实中一大类舞蹈正是这么来的(模仿动物/器物)。本质上我们造了"一个会模仿的身体"。

## 2. 技术路线:演进史与现状

### 2.1 走过的弯路(都有价值,留作原理参考)

| 阶段 | 做法 | 结果 |
|------|------|------|
| RL 训练肌肉 | MuscleMimic 式 RL 在肌肉上学跳舞 | **否决**:① 本机算力不可行(编译/吞吐墙,见 `compile_bottleneck_findings.md`);② RL 会发明"能拿分但不像人"的发力(奖励黑客),与"自然"冲突 |
| 自建 MuJoCo 逆向 | ID → 肌肉冗余 QP(自己写) | **撞墙**:所需关节力矩超肌肉能力 ~100×,肌肉只满足 3%。根因:手搓时排除膝耦合 DOF 削掉了肌肉杠杆 + 浮动基座 GRF。见 `biomechanics_inverse_approach.md` |
| **转 OpenSim** | 用成熟生物力学工具(用户定:用已有研究成果) | **成功验证路线**(见下) |

### 2.2 现状(2026-06-03)

**已扎实(✅)**:
- **OpenSim Static Optimization 证明路线成立**:正确处理膝/肩约束后,**肌肉能产出整段舞蹈的全部关节力矩**(腿/腰/臂储备≈0)。手搓时的可行性病理消失。唯一大残差 = pelvis_ty≈体重 = 缺 GRF(预期,可后补)。
- 工具链全通:`pip install opensim`(4.6,WSL/Linux,**含 Moco**)、模型 `cyclistFullBodyMuscle.osim`(与 MyoFullBody 同源)、运动按坐标名转 `.mot`、MuJoCo 按激活上色渲染。
- 愿景在趋势上验证过:前向跟踪中**越弱的身体偏离越多**。

**核心难点(🔴 这条路最硬的一环)**:
> **干净的"能力受限前向跟踪"是难题**:力模型自洽 + 饱和区行为 + 前向稳定,三者纠缠。**这正是当初用 RL 的原因。**
- Static Optimization 是"精确复现"(储备兜底),**不实现愿景**(§1.1)。愿景需要**前向**方法。
- MocoTrack/MocoInverse:轨迹优化把"所有时刻×几百肌肉"耦合成巨型 NLP,本机**算力不可行**。
- 自建 MuJoCo 前向 CMC:逐DOF夹断→振荡;肌肉空间QP→力不自洽+无饱和。两版都没干净解决。
- **当前尝试:OpenSim CMCTool**(专为能力受限肌肉跟踪而生,处理了力模型自洽+稳定性)。

### 2.3 关键技术事实(别重新踩坑)

- `pip install opensim`(4.6)在 **Linux 就带 Moco/MocoInverse**(网上"Linux 要源码编译"是过时信息)。
- 大肌肉模型上:**Static Optimization / CMC(逐帧/前向)远比 Moco(轨迹优化)可行**。
- Moco 不支持 locked 坐标 → `ModOpReplaceJointsWithWelds` 焊掉(肋骨/腕/mtp/胸椎)。SO 原生支持 locked。
- OpenSim AnalyzeTool/CMCTool 的可靠用法:配置后 `printToXML` 存 setup,再从 XML 重载 `run()`。
- 模型坐标名 = OpenSim 原生名(`hip_flexion_r`/`knee_angle_l`/`elv_angle_r`/`L4_L5_FE`…),所以 MyoFullBody qpos 能按名直接转 `.mot`。
- 储备/残差:pelvis 残差 optimalForce 大(扛 GRF 缺口),关节储备小/贵(逼肌肉干活)。
- 详细 API 坑见 memory `reference-opensim-moco-wsl`。

## 3. 路线图

1. **实现干净的 B(能力受限前向跟踪)** ← 当前焦点
   - 路径:OpenSim CMCTool;兜底:更工程化的自建控制器 / 剪枝模型上的小范围 RL。
   - 验收:同一段舞,F_max 三档(常人/×2.5/×0.7)跳出**明显不同且自然**的质感;强档紧跟、弱档自然够不到。
2. **补 GRF**:从 COM 动力学估地面反力,让腿部肌肉生理化(消除 pelvis_ty 残差)。
3. **渲染对比**:F_max 角色档的肌肉驱动视频(MuJoCo 按激活上色)。
4. **UE/MetaHuman 烘焙**:把仿真动作导成 AnimSequence/FBX,在 UE 5.6 里 MetaHuman 跳。游戏可用 + LOD。
5. **通用化(任意输入)**:从关节角跟踪推广到**关键点跟踪**,支持非人输入 → "任意动作→模仿/舞蹈"。
6. **手指/风格层**:手指无质量/不承重,单独风格层(见 design.md §2B),不走肌肉物理。
