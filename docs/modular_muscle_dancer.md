# 模块化肌肉舞者 — 完整设计

> 核心设计文档(非必读但建议接手者读)。记录"自主可控、本机可训"路线的完整架构。
> 2026-06-03。前置:[decision_muscle_training_paths.md](decision_muscle_training_paths.md)、[training_overview.md](training_overview.md)。

## 0. 背景:为什么走到这

- 目标:**肌肉驱动**的舞蹈,可进 UE/游戏、可分级(LOD)。
- 撞墙实况(本会话验证):
  - 全 354 肌肉从零训,在单 A6000+WSL 上**不实际**——编译 ~2–3.5h(且不缓存)、训练 ~3h/千步,要几周才会站;
  - 预训练权重路线因配置/观测不匹配 + Pop 重度 OOD,**主动放弃**;
  - **bimanual(手臂,几十块肌肉)在本机 17 分钟编完、能训、出了挥手视频** —— 这是唯一被验证"本机真能编能训"的肌肉形态。
- **决策**:走务实、自主可控路线 = **把控制拆成本机能训的模块,各自训练,在连接关节处合成**。

## 1. 核心原则:拆"控制模块",而不是删肌肉

> 删肌肉会伤舞蹈保真度(脊柱、手对舞蹈都重要)。所以**全保真保留肌肉**,靠**把控制分解成模块**来获得可训练性。

- 一个**完整的物理身体**(脊柱、手都在);
- 控制被拆成**若干策略,各控制一个不相交的肌肉子集**;
- 每个模块**在自己的小物理子模型上单独训练**(小问题 = 本机扛得动);
- 在**连接关节**处通过"边界位姿"耦合、合成。

## 2. 模块分解(边界)

| 模块 | 范围 | 连接关节(边界) | 规模 | 本机可训? |
|------|------|-----------------|------|-----------|
| **身体核心** | 腿 + 躯干/脊柱 + 颈 + 上臂到腕 | (根:骨盆) | 大(~290 肌肉) | ⚠️ 仍是硬骨头(见 §3) |
| **左手** | 腕以下:腕骨 + 手指 | 左腕 | 小(~30 肌肉) | ✅ bimanual 量级 |
| **右手** | 腕以下 | 右腕 | 小 | ✅ |

**为什么腕是好边界**:手很轻 → 对手臂的动力学反作用小;手内部动作(指型)在**给定腕位姿后基本自决**;手子树在运动链里干净地挂在腕下。
→ 这与之前否掉的"上下身硬切"本质不同:那是切**强耦合、定平衡**的核心;这是摘**远端轻附件**。

**(可选/待评估)** 手臂能否也作为模块(挂肩)? 手臂比手重、对平衡影响更大、且是 Pop 的主要可见动作 → **耦合风险高,暂不拆**,留作以后评估。

## 3. 诚实的难点:身体核心仍然大

**模块化优雅地解决了"手",但没解决"身体核心"。**

- 身体核心(腿+脊柱+臂)是**强耦合的协同单元**(平衡、body wave),**不能再干净拆**;
- 摘掉手只把 354 → ~290,**编译仍是小时级、训练仍慢**;
- 所以身体核心是**仍需正视的 tractability 瓶颈**,选项见 §12。

> 不粉饰:本设计让**手得到全保真且可训**、让整体架构对(分层/LOD/复用),但**身体核心的"训得动/训得快"仍要单独攻**。

## 4. 每个模块的构成

每个模块 = `{肌肉子集, 观测, 策略网络, 自己的训练子模型, 参考动作子集}`。
- **身体核心**:控制腿/脊柱/臂肌肉;观测 = 全身本体感觉 + 身体参考姿态;在"无手指身体模型"上训。
- **手模块**:控制手部肌肉;观测 = **手指本体感觉 + 腕/前臂状态(边界条件)**;在"前臂+手"小模型上训(类 bimanual)。

## 5. 连接机制("怎么接")

- **训练时**:手模块把**腕当驱动边界**——用真实腕运动(来自身体模块/参考)作为条件输入来训;身体模块单独训(腕以下当末端,不含手指自由度或冻结)。
- **接的方式**:手模块的**输入里带腕/前臂位姿与速度**(由身体模块提供),输出手部肌肉激活;两个策略控制不相交肌肉子集,**在腕关节处通过位姿耦合**。
- **训练顺序**:先训身体核心 → 它产出"腕轨迹分布" → 用这些腕轨迹**条件化训练手模块** → 合成。(也可后续联合微调。)

## 6. 合成方式(关键取舍,待锁)

| | (a) 运动学拼接 | (b) 全身物理合成 |
|---|---|---|
| 做法 | 身体模型出腕轨迹 → 喂手模型出指动作 → **拼接** | 各模块策略一起在**全身物理**上跑 |
| 编译 | **永不碰全身大图**(各跑小模型)✅ | 要付一次全身编译 ❌ |
| 物理一致性 | 近似(手与身体不在同一物理解算) | 严格一致 |
| 本机契合 | **高**(最省) | 低(回到编译墙) |

→ **推荐 (a) 运动学拼接**:全程不碰 354 全身大图,最契合本机;手相对身体的物理反作用小,近似可接受。最终进游戏本就是烘焙动画,(a) 足够。

## 7. 脊柱:只能很轻处理(面向舞蹈)

- 舞蹈核心(body wave / isolation / 躯干 pop)全靠脊柱 → **保留脊柱肌肉,最多极轻简化**;
- 不做之前"砍 184 块 L3"的激进方案;
- 若为身体核心 tractability 必须减一点,**只动最末梢、对舞蹈无感的几块**,且**被动定住不焊死**(§9)。

## 8. 手 / 手指:作为手模块全保真

- 手指对舞蹈重要 → **不阉割,放进手模块完整训练**(用同一套 RL-on-muscles 套路,规模小、本机能训);
- 这正是"想全面"的落点:手不是被删,而是**有自己专属、全保真的模块**。

## 9. 冻结关节:被动定住,不焊死

任何因 tractability 暂不驱动的关节(若有):
- **保留关节自由度**,加刚度/阻尼让它定住(不乱晃);
- **不 weld 焊死** → 将来要把它纳入某模块,**直接挂回肌肉即可**;
- 记录"哪些被冻、怎么解冻"。

## 10. 与分层 / LOD / 游戏运行时的衔接

- **运行时不跑肌肉物理**——离线生成动作 → 烘焙成动画/MetaHuman,游戏里廉价播放;
- 模块天然支持 LOD:远处只用身体模块(无手指细节),近处加手模块;
- 对应你"主要动作 / 细节动作"分层:身体核心=主,手=细节模块。

## 11. 肌肉 L1/L2/L3 数据(支撑 coarse-to-fine)

实测(354 肌肉,disable_fingers):
- **L1 ≥500N:86 块,占 80% 力**(soleus/vastus/腘绳肌/腓肠肌/冈下肌 = 腿+肩主力);
- **L2 100–500N:84 块,占 16%**;
- **L3 <100N:184 块,仅占 4%**(逐节脊柱细肌 5–7N)。

用途:**不是用来删**(§7 已否),而是用于**身体核心的"由粗到精"训练课程**——先让 L1 把整体撑起来、再放开 L2/L3 精修(加速学习,§12)。

## 12. 身体核心 tractability 的选项(诚实)

身体核心仍大,攻法(可组合):
1. **由粗到精课程**:先只训 L1(86 块,撑住整体),再逐级放开 → 早期阶段问题小、学得快(降**训练成本**,不降编译);
2. **极轻减末梢肌**(§7 范围内)→ 略降编译;
3. **接受一次性长编译**:身体核心编一次(几小时),之后**冻结配置**复用(注意:全身大图当前不缓存,但若身体核心用纯 jax-MJX 子模块或更小规模,可能可缓存——待验证);
4. **必要时局部上云**:只有身体核心这一块若真训不动,再考虑外部算力。

## 13. 分阶段构建计划

1. **阶段 A — 先做"手模块"(低风险、已被证明可训)**:在"前臂+手"小模型上,用现有 RL 套路训一个手部肌肉控制器,腕为驱动边界。验证:本机快编快训(对标 bimanual)、能跟手部参考。
2. **阶段 B — 身体核心**:在"无手指身体"模型上训身体主动作(可上 §12 的由粗到精)。这是最难的一块,单独攻。
3. **阶段 C — 连接合成(运动学拼接)**:身体出腕轨迹 → 喂手模块出指动作 → 拼接成整支舞 → 渲染。
4. **阶段 D — 烘焙进 UE/MetaHuman**(对接最初产品目标)。

> 顺序刻意:先做**确定能成的手模块**(快速正反馈 + 验证套路),再啃身体核心。
